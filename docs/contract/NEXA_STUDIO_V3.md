کتابچه اجرایی و الزام‌آور Nexa Studio — نسخه ۳٫۰

این سند قرارداد ساخت است، نه پیشنهاد. هر جمله با «باید» یا «ممنوع» الزام است. سازنده (انسان یا ایجنت) بدون تأیید مکتوب مالک حق ندارد الزامی را حذف، تغییر یا به فاز بعد موکول کند. هر الزام شناسه دارد (مثل R-12) و فقط وقتی «انجام‌شده» است که شواهد آزمون آن در گزارش ثبت شده باشد. مبنا: بررسی مستقیم مخزن davoodmehraban89/nexa-dev-bot در ۲۴ اکتبر ۲۰۲۶.

۰. قواعد حاکم بر ساخت

R-01 — خروجی ساختگی ممنوع. هر صفحه باید به API واقعی وصل باشد. داده نمونه، دکمه بی‌اثر، موفقیت ساختگی و «به‌زودی» در ساخت ممنوع است. هر قابلیت یا کامل و آزموده است یا در UI وجود ندارد.

R-02 — ترتیب فازها. G0 ← G1 ← G2 ← G3 ← G4. عبور از هر دروازه فقط با شواهد بخش ۱۱.

R-03 — شواهد. هر PR باید شامل شرح تغییر، لینک CI روی SHA دقیق، خروجی تست، و برای هر قابلیت UI یک ویدئوی کوتاه از دستگاه واقعی باشد.

R-04 — الزام سند برنده است. هرجا ساخت ساده‌تر با این سند تعارض داشت، سند اجرا می‌شود.

R-05 — ابهام. سازنده فرض خود را در گزارش می‌نویسد و ساده‌ترین گزینه امن را اجرا می‌کند. فقط برای تصمیم‌های بخش ۱ باید از مالک بپرسد.

R-06 — حفظ کد موجود. بازنویسی از صفر ممنوع است. تست‌های موجود باید سبز بمانند و هر تغییر رفتاری با تست RED سپس GREEN همراه باشد.

R-07 — راز. توکن، کلید و متن منبع کاربر در لاگ، Audit، callback_data، URL، پیام تلگرام و کامیت ممنوع است.

۳. مرکز اتصال GitHub (الزام اصلی این نسخه)

هدف قابل‌آزمون: کاربر عادی و بدون دانش فنی، فقط با خواندن راهنمای داخل برنامه، در کمتر از ۵ دقیقه حساب GitHub خود را وصل می‌کند، همه مخازنش را می‌بیند و روی آن‌ها کار می‌کند.

۳.۱ الزام‌های عمومی

C-01 صفحه «اتصال‌ها» دو کارت دارد: «ورود با GitHub» (روش A) و «اتصال با توکن — راهنمای گام‌به‌گام» (روش B). در M0 فقط کارت دوم نمایش داده شود.

C-02 هر دو روش یک خروجی دارند: یک ردیف در github_connections با auth_type برابر app_user یا fine_grained_pat. بقیه سیستم نباید بین دو نوع فرق بگذارد.

C-03 کاربر می‌تواند چند اتصال داشته باشد (یکی برای حساب شخصی، یکی برای هر سازمان).

C-04 پس از اتصال، فهرست کامل مخازن (همه صفحه‌ها) با سوئیچ «فعال در Nexa» برای هر مخزن و دکمه «فعال‌سازی همه» نمایش داده شود. پیش‌فرض همه غیرفعال است و Nexa فقط روی مخزن فعال عمل می‌کند (Grant).

C-05 وضعیت هر اتصال یکی از این‌هاست: فعال، در حال انقضا (۱۴ روز یا کمتر)، منقضی، نیازمند توجه، قطع‌شده. دکمه‌ها: «بررسی دوباره»، «تعویض توکن»، «قطع اتصال».

۳.۳ اعتبارسنجی سروری توکن

C-10 قالب: عبارت ^github_pat_[A-Za-z0-9_]{20,255}$. پیشوندهای ghp_، gho_، ghu_، ghs_، ghr_ و هر چیز دیگر رد شود با پیام: «این نوع توکن دسترسی گسترده دارد. توکن Fine-grained بساز.»

C-11 فراخوانی GET https://api.github.com/user با توکن. پاسخ 401 → «توکن نامعتبر است یا منقضی شده.»

C-12 هدر github-authentication-token-expiration باید خوانده شود. نبودن هدر (توکن بدون انقضا) یا انقضای کمتر از ۷ روز → رد با توضیح فارسی.

C-13 فهرست مخازن با GET /user/repos?per_page=100&sort=updated و پیمایش کامل هدر Link؛ اگر Resource owner یک سازمان بود، GET /orgs/{org}/repos هم خوانده شود. فهرست گروه‌بندی‌شده بر اساس owner نمایش داده شود.

C-15 آزمون خواندن بدون اثر جانبی: خواندن ریشه Contents، فهرست PRها و فهرست Actions روی یک مخزن؛ برای هر مجوز نتیجه «خواندن تأیید شد» یا «دسترسی ندارد» نمایش داده شود. مجوزهای نوشتن فقط در گام ۷ آزموده می‌شوند.

C-16 گام ۷: ساخت شاخه nexa/connection-test-<8hex> از HEAD شاخه پیش‌فرض و حذف همان شاخه، با Safe Approval از نوع WRITE. خطای 403 باید نام مجوز گمشده را بگوید (مثلاً «Contents: Read and write را فعال کن»). هیچ فایل یا شاخه دیگری نباید ساخته یا حذف شود.

C-17 ذخیره: توکن با AES-GCM رمز شود؛ در D1 فقط این‌ها نگهداری شود: last4، پیشوند، expires_at، github_login، github_user_id، resource_owner، created_at، last_verified_at، status.

C-18 توکن هرگز به Client برنمی‌گردد. UI فقط github_pat_••••ab12 نشان می‌دهد.

C-19 اتصال مجدد برای همان github_user_id و resource_owner = تعویض توکن، نه اتصال دوم.

C-20 هر github_user_id فقط به یک کاربر Nexa متصل می‌شود. اتصال دوم رد شود: «این حساب GitHub قبلاً به کاربر دیگری وصل است.»

C-21 پایش انقضا با Cron Trigger روزانه؛ اعلان تلگرام در ۱۴، ۳ و ۰ روز مانده؛ پس از انقضا همه عملیات آن اتصال رد و وضعیت «منقضی» شود.

C-22 پاسخ 401 یا 403 از GitHub → وضعیت «نیازمند توجه» + پیام فارسی مشخص؛ تلاش مجدد بی‌پایان ممنوع.

C-23 قطع اتصال: حذف توکن رمزشده، لغو Grantها، پاک‌کردن Workspaceهای وابسته. UI باید بگوید: «Nexa نمی‌تواند توکن را در GitHub باطل کند؛ آن را از https://github.com/settings/personal-access-tokens هم حذف کن.»

C-24 همه رویدادهای اتصال (ساخت، تأیید، تعویض، خطا، قطع) بدون توکن در Audit ثبت شود.

۳.۴ محافظت از توکن در تلگرام

C-30 توکن فقط داخل Mini App وارد می‌شود. اگر پیام متنی به ربات با الگوی github_pat_ یا ghp_/gho_/ghu_/ghs_/ghr_ شروع شد، ربات باید فوراً آن پیام را با deleteMessage حذف کند، هشدار «توکن در چت قرار گرفت و باید در GitHub باطل شود» با لینک حذف بدهد و محتوا را هرگز پردازش، ذخیره یا لاگ نکند.

C-31 فیلد توکن: type=password، autocomplete=off، autocapitalize=off، spellcheck=false؛ پس از ارسال مقدار از DOM پاک شود؛ ذخیره در localStorage یا URL ممنوع.

C-32 ارسال فقط با POST /api/v1/connections/pat و بدنه JSON، بدون کش. ثبت بدنه درخواست در لاگ ممنوع و با تست خودکار (middleware پاک‌سازی) قفل شود.

C-33 حداکثر ۵ تلاش اتصال در ساعت برای هر کاربر.

C-34 محدودیت‌های شناخته‌شده باید در گام ۱ و ۳ نمایش داده شوند: توکن Fine-grained فقط یک Resource owner دارد؛ مخزن‌های حساب دیگران که تو فقط Collaborator آن‌ها هستی با این توکن در دسترس نیستند؛ سازمان‌ها ممکن است PAT را غیرفعال کرده یا تأیید مالک سازمان بخواهند. برای هر سازمان یک اتصال جداگانه بساز.

۳.۵ روش A: ورود با GitHub (GitHub App)

A-01 ثبت GitHub App با گزینه‌های «Request user authorization (OAuth) during installation» و «Expire user authorization tokens» روشن؛ Webhook با secret؛ حداقل مجوز: Contents Read and write، Pull requests Read and write، Actions Read-only، Metadata Read-only؛ Callback = https://<دامنه>/api/v1/connections/github/callback.

A-02 جریان: state تصادفی یک‌بارمصرف ۱۰ دقیقه‌ای وابسته به سشن ← تبادل code ← دریافت access و refresh token (مدت انقضا از پاسخ expires_in خوانده شود، نه ثابت در کد) ← GET /user، GET /user/installations، GET /user/installations/{id}/repositories.

A-03 هر installation_id از URL نادیده گرفته شود؛ فقط از GET /user/installations پذیرفته می‌شود.

A-04 چرخش refresh token اتمیک ذخیره شود؛ شکست refresh → وضعیت «نیازمند ورود دوباره».

A-05 Webhookهای installation، installation_repositories و github_app_authorization پس از بررسی امضای X-Hub-Signature-256، ظرف ۶۰ ثانیه Grantها را به‌روز کنند.

A-06 نوشتن روی GitHub همیشه با توکن کاربر. نوشتن با توکن نصب ممنوع است.

A-07 تا وقتی App ثبت و آزمون نشده، کارت روش A در UI نمایش داده نشود (R-01).

رمزنگاری (S-01 تا S-05):

S-01 توکن‌ها و secret TOTP با AES-GCM-256، IV تصادفی ۱۲ بایتی برای هر رکورد و AAD برابر user_id|record_id رمز شوند.

S-02 کلید master در Secrets با شناسه نسخه (key_id) نگهداری شود و سازنده باید روال چرخش کلید را بنویسد و یک‌بار روی داده آزمایشی اجرا کند.

S-03 هیچ جدول، لاگ یا پاسخ API نباید توکن خام یا متن Draft را ذخیره/برگرداند.

S-04 حذف حساب کاربر باید همه توکن‌ها، Grantها، Workspaceها و Audit مربوط را طبق سیاست نگهداری پاک یا ناشناس کند؛ سازنده سیاست نگهداری Audit را (پیشنهاد: ۹۰ روز) در docs/retention.md بنویسد.

S-05 مهاجرت مالک: مالک توکن Fine-grained خود را با ویزارد بخش ۳ وصل کند؛ پس از تأیید، GITHUB_TOKEN و defaultOwner از کد و از Secrets حذف شوند (wrangler secret delete GITHUB_TOKEN). چون wrangler.jsonc مقدار keep_vars: true دارد، حذف باید در داشبورد Cloudflare هم تأیید و شاهدش ثبت شود.

۵. هویت، سشن و دسترسی

I-01 ورود: initData معتبر ← کاربر دعوت‌شده/فعال ← سشن امضاشده ۱۵ دقیقه‌ای. پس از آن initData در هر درخواست ارسال نشود.

I-02 تلگرام‌آیدی ناشناس: فقط پیام «برای استفاده به دعوت نیاز داری» + فیلد کد دعوت. هیچ داده‌ای نمایش داده نشود. کد دعوت یک‌بارمصرف، هش‌شده و دارای انقضا باشد.

I-03 user_id فقط از سشن سرور می‌آید؛ هر userId/ownerId در بدنه یا URL کلاینت نادیده گرفته شود.

I-04 هر repoId سمت کلاینت اشاره‌گر است: پیش از خواندن، Grant فعال بررسی شود؛ پیش از نوشتن، دسترسی از GitHub دوباره تأیید شود (کش حداکثر ۶۰ ثانیه).

I-05 Approval به userId + action + repoId + baseSha + digest گره می‌خورد و یک‌بارمصرف است (R-16).

I-06 قطع اتصال، حذف نصب یا انقضای توکن → درخواست‌های بعدی ظرف ۶۰ ثانیه رد شوند.

I-07 کاربر suspended هیچ عملیاتی (حتی خواندن) نداشته باشد.

I-08 هر خطا صریح نمایش داده شود؛ موفقیت ساختگی ممنوع (حفظ رفتار فعلی کد).

۶. معماری و ماژول‌های جدید

حذف از MVP: Supabase، Neon، Render، Railway، VPS/Docker.
