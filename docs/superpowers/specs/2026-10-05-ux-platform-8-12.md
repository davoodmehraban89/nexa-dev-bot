# Nexa Dev — UX & Platform Development (Roadmap 8–12)

## 8 — Developer Copilot
Evidence-grounded assistive layer. It may summarize source-backed operational evidence and propose declared actions, but it cannot mutate providers directly. Mutation remains behind Plugin Router, central policy and Safe Approval.

## 9 — Browser QA
QA results are evidence records with pass/fail/blocked states. Missing evidence is blocked rather than fabricated success. Browser execution is adapter-driven; the core evaluator never claims a live browser run by itself.

## 10 — Plugin Catalog
Owner-visible catalog is derived from declared plugin manifests/actions and their risk classifications. Catalog discovery does not grant execution authority and cannot override policy.

## 11 — Multi-project Portfolio
Bounded owner-scoped project summaries normalize only source-backed health states. Unknown/unavailable evidence remains unknown; no synthetic health status is emitted.

## 12 — Unified Command Center
A single Telegram entry point exposes rows 8–12 with compact callback-safe navigation. Search/result surfaces are bounded and preserve existing main-menu recovery.

## Shared acceptance
Owner-only boundary remains authoritative; no secret/source/draft/approval token persistence is added; no direct provider mutation path is added; false-success is prohibited; Telegram callbacks remain compact; all five capabilities have regression coverage.
